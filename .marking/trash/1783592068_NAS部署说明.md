# CatPaw2API NAS 部署说明

本文档用于把 CatPaw2API 部署到 Debian/FnOS/群晖等支持 Docker 的 NAS。

## 部署方式

推荐使用 Docker Compose。

部署后访问：

```text
http://<NAS-IP>:8766/
```

OpenAI-compatible Base URL：

```text
http://<NAS-IP>:8766/v1
```

## 文件说明

新增部署文件：

```text
Dockerfile
docker-compose.yml
.dockerignore
.env.nas.example
deploy/nas-up.sh
deploy/nas-down.sh
```

持久化目录：

```text
data/
  accounts.json
  catpaw2api.log

secrets/
  catpaw-extension.js
```

## 关键前提

CatPaw 的 chat completions 请求需要加密。加密密钥来自 CatPaw Desktop 插件的 `extension.js`。

Windows 本机路径通常是：

```text
%LOCALAPPDATA%\Programs\CatPawAI\resources\app\extensions\mt-idekit.mt-idekit-code\out\extension.js
```

部署到 NAS 后，需要把它复制到项目目录：

```text
secrets/catpaw-extension.js
```

如果没有这个文件：

```text
WebUI 可以打开
账号可以导入
登录接口部分可用
但 /v1/chat/completions 会因为找不到 CatPaw encryption keys 失败
```

## 在 NAS 上部署

### 1. 上传项目

把整个项目目录上传到 NAS，例如：

```text
/volume1/docker/catpaw2api
```

或者：

```text
/opt/catpaw2api
```

建议不要上传这些目录：

```text
node_modules/
.venv/
captures/
catpaw2api.log
catpaw2api.process.log
```

Docker 构建时会自动安装 Node 依赖。

### 2. 准备目录

在 NAS SSH 里执行：

```bash
cd /volume1/docker/catpaw2api
mkdir -p data secrets
cp .env.nas.example .env
```

编辑 `.env`：

```bash
nano .env
```

默认配置：

```env
CATPAW_PORT=8766
CATPAW_PROXY=
CATPAW_LOGIN_PROXY=
CATPAW_VERIFY_TLS=true
CATPAW_UPSTREAM_TIMEOUT_MS=60000
CATPAW_SSO_SECRET=
```

如果需要本地 API key：

```env
CATPAW_API_KEY=change-me
```

### 3. 复制 CatPaw extension.js

从 Windows 复制：

```text
C:\Users\<你>\AppData\Local\Programs\CatPawAI\resources\app\extensions\mt-idekit.mt-idekit-code\out\extension.js
```

到 NAS：

```text
/volume1/docker/catpaw2api/secrets/catpaw-extension.js
```

也可以用 scp：

```bash
scp "%LOCALAPPDATA%\Programs\CatPawAI\resources\app\extensions\mt-idekit.mt-idekit-code\out\extension.js" \
  root@<NAS-IP>:/volume1/docker/catpaw2api/secrets/catpaw-extension.js
```

Windows PowerShell 更稳的写法：

```powershell
scp "$env:LOCALAPPDATA\Programs\CatPawAI\resources\app\extensions\mt-idekit.mt-idekit-code\out\extension.js" `
  root@<NAS-IP>:/volume1/docker/catpaw2api/secrets/catpaw-extension.js
```

### 4. 启动

```bash
cd /volume1/docker/catpaw2api
chmod +x deploy/nas-up.sh deploy/nas-down.sh
./deploy/nas-up.sh
```

或直接：

```bash
docker compose up -d --build
```

旧版 Docker：

```bash
docker-compose up -d --build
```

### 5. 查看状态

```bash
docker compose ps
docker compose logs -f catpaw2api
```

健康检查：

```bash
curl http://127.0.0.1:8766/health
```

局域网访问：

```text
http://<NAS-IP>:8766/
```

## 使用方式

### 导入认证文件

推荐在 NAS 上使用“认证文件上传”：

```text
WebUI -> 账号 -> 认证文件导入
```

标准账号 JSON 文档：

```text
账号认证文件格式.md
认证文件上传与批量导入说明.md
examples/auth-accounts.sample.json
```

### 手机号/Yoda 登录

NAS 上也可以使用 WebUI 登录链路：

```text
登录 CatPaw -> 开始 CatPaw 登录 -> 手机号验证码 / Yoda -> 导入账号
```

Yoda 不会被绕过，需要用户在浏览器里手动完成官方滑块。

### State DB 导入

NAS 默认没有 Windows CatPawAI 的 `state.vscdb`，所以不建议依赖“导入 State DB”。

如果你把 Windows 的 `state.vscdb` 也复制到 NAS，可以在 WebUI 手动填路径导入，但更推荐使用认证文件导入或手机号登录。

## 反向代理

如果用 Nginx/Caddy 反代：

```text
http://127.0.0.1:8766
```

需要支持 SSE：

```nginx
proxy_http_version 1.1;
proxy_set_header Connection "";
proxy_buffering off;
proxy_read_timeout 600s;
```

OpenAI Base URL 可设置为：

```text
https://your-domain.example/v1
```

## 更新

上传新代码后：

```bash
cd /volume1/docker/catpaw2api
docker compose up -d --build
```

账号数据保存在：

```text
data/accounts.json
```

不会因为重建镜像丢失。

## 排错

### 容器启动但无法访问

检查：

```bash
docker compose ps
docker compose logs --tail=100 catpaw2api
ss -lntp | grep 8766
```

Compose 里已经设置：

```env
CATPAW_HOST=0.0.0.0
```

如果 NAS 防火墙拦截，需要放行 `8766/tcp`。

### /v1/chat/completions 报 encryption keys not found

缺少：

```text
secrets/catpaw-extension.js
```

确认：

```bash
ls -lh secrets/catpaw-extension.js
docker compose exec catpaw2api ls -lh /app/secrets/catpaw-extension.js
```

### 账号为空

第一次部署不会自动有账号。进入 WebUI：

```text
账号 -> 认证文件导入
```

或：

```text
登录 CatPaw -> 手机号登录
```

### 需要代理

编辑 `.env`：

```env
CATPAW_PROXY=http://host.docker.internal:7890
CATPAW_LOGIN_PROXY=http://host.docker.internal:7890
```

Linux Docker 下 `host.docker.internal` 不一定可用。更稳的是填 NAS 能访问的代理 IP，例如：

```env
CATPAW_PROXY=http://192.168.1.10:7890
CATPAW_LOGIN_PROXY=http://192.168.1.10:7890
```

然后重启：

```bash
docker compose up -d
```

### 查看应用日志

容器日志：

```bash
docker compose logs -f catpaw2api
```

应用日志：

```bash
tail -f data/catpaw2api.log
```
